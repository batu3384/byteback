## CA-002 | Kritik | İşlev | ntfs_parser.cpp:174 ve :394

**Kanıt:** `NTFSParser::scan` BPB’yi LBA 0’dan okur (`bootSector[0x0D]` = sectors-per-cluster, satır 174-176). GPT/MBR fiziksel diskte LBA 0 koruyucu MBR’dir, NTFS boot değil. Data run çevirisi `run.startSector = previousLcn * sectorsPerCluster` (satır 394) — LCN hacim görelidir, disk LBA’sı değil; `partitionStart` eklenmez. `NTFSParser`’ın `scanAt`’i yok; hızlı tarama NTFS’i hep ofset 0’da çağırır (`scan_coordinator.cpp:121-122`). USN geçişi aynı `run.startSector * sectorSize` ile okur (satır 586).

**Neden:** Windows GPT (EFI + Basic Data) ve modern MBR (bölüm genelde LBA 2048) için MFT FILE sihirleri fiziksel olarak bulunur, ama küme→sektör haritası yanlıştır. Kurtarma (CA-001 düzeltilse bile) yanlış LBA’dan okur. FAT tarafında `scanAt(partitionOffset)` var; NTFS aynı düzeltmeyi almamış.

**Yön:** NTFS boot’u bölüm başlangıcında (`OEM "NTFS    "` + 0x55AA) bul. SPC ve `bytesPerCluster` oradan. Fiziksel sektör = `partitionStartLba + lcn * spc`. Hızlı taramada GPT/MBR “Windows Basic Data” / 0x07 için `scanAt`.

1. CA-001 — Run geometrisini DB+IPC+UI’da taşı; kurtarmayı LBA 0 yedeğinden çıkar.
2. CA-002 — NTFS boot’u bölümde oku; LCN’ye partition tabanı ekle.
3. CA-003 — Sanal RAID’i DiskReader/tarama/kurtarma yoluna bağla; bozuk üyede `fail_disk`.
4. CA-004 — Bölüm tipini GUID/boot imzasıyla ayır; her parser `scanAt`.
5. CA-006 — `getScanState` adlı sütun seçsin (CA-005 kötü sektör kopyası aynı turda ucuz).
